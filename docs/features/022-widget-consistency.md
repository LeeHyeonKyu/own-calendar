# 위젯 타임존/태스크/공휴일 일관성

위젯 API의 날짜 처리를 KST 기준으로 통일하고, 월간 위젯에 태스크 상세와 공휴일 데이터를 추가한다.

## Problem

위젯 API(`server/src/routes/widget.ts`)가 UTC 기준으로 날짜 key를 생성해서, 종일 이벤트/태스크가 위젯에서 하루 전으로 표시된다. DB에 `2026-10-17 15:00:00` (UTC = KST 10/18 자정)으로 저장된 태스크가 `taskDays["17"]`에 매핑되어 17일에 orange dot이 찍힌다.

또한 월간 위젯의 선택일 패널이 이벤트만 표시하고 태스크 상세를 보여주지 않아서, dot이 있는 날짜를 눌러도 "일정이 없습니다"가 나온다. 공휴일 데이터도 위젯 API에서 전혀 반환하지 않아 메인 앱과 불일치한다.

실제 데이터로 확인:
- `Task "클라이밍"`: `scheduledDate = 2026-10-17 15:00:00` (KST 10/18) → `taskDays["17"]`에 매핑
- `events["17"]` = 빈 배열, `events["18"]` = 빈 배열 → 17일/18일 모두 상세 없음

## Value

PROJECT.md "데이터 조작의 자유" 원칙 — 등록한 데이터가 위젯에서 올바르게 보이지 않으면 위젯을 신뢰할 수 없다. Leading Indicator("매일 아침 이 앱을 첫 번째로 여는가")에 직접 영향 — 위젯이 정확하면 앱을 열지 않아도 일정 파악이 가능해 습관이 고착된다.

## Solution

1. **위젯 API KST 변환**: `widget.ts`의 `/monthly`와 `/today` 엔드포인트에서 날짜 계산 시 KST 오프셋(+9시간) 적용. DB 스키마는 변경하지 않음.
2. **태스크 상세 맵 추가**: `/monthly` 응답에 `tasks: { "18": [{ title, status, ... }] }` 맵 추가. iOS 위젯에서 선택일 패널에 태스크 표시.
3. **공휴일 데이터 추가**: `/monthly` 응답에 `holidays: { "3": "개천절", ... }` 맵 추가 (사용자의 HolidaySubscription 기반). iOS 위젯에서 공휴일 날짜 강조.

접근 방식 결정 근거: DB 스키마 변경(DATE 컬럼 추가)은 업계 표준이지만, 마이그레이션 + 전체 서비스 레이어 수정이 필요. 현재 사용자가 KST 단일 타임존이므로 서버 API 레이어 변환으로 충분하다. 다중 타임존 지원이 필요해지면 그때 스키마를 변경한다.

## Scope

**Includes:**
- `widget.ts` `/monthly`: dayKey 생성 시 KST 변환 (이벤트 + 태스크)
- `widget.ts` `/today`: todayStart/todayEnd를 KST 기준으로 계산
- `widget.ts` `/monthly`: 응답에 `tasks` 상세 맵 추가
- `widget.ts` `/monthly`: 응답에 `holidays` 맵 추가 (holidayService 호출)
- iOS 월간 위젯: 선택일 패널에 태스크 상세 표시
- iOS 월간 위젯: 공휴일 날짜 시각적 표시 (빨간색)
- iOS 월간 위젯: 선택일 패널에 공휴일 이름 표시

**Excludes:**
- today 위젯(오늘 일정)의 공휴일 표시 — monthly만
- DB 스키마 변경 / 데이터 마이그레이션
- 메인 앱(Flutter) 수정 — 앱에서는 정상 동작
- 새로운 위젯 종류 추가
- 다중 타임존 지원 — 현재 KST 단일 사용자

## Approach

- `widget.ts`에 KST 변환 유틸리티 추가: `const KST_OFFSET = 9 * 60 * 60 * 1000`
- 종일 이벤트/태스크의 dayKey 계산 시 KST 오프셋 적용
- `/monthly` 응답 스키마 확장: `tasks`, `holidays` 맵 추가
- `WidgetAPIClient.swift`의 `MonthlyAPIResponse` 모델 확장
- `OwnCalendarMonthlyWidget.swift`의 `EventsListView`에 태스크 섹션 추가
- 공휴일은 `holidayService.getHolidays()` 호출하여 day → name 맵 생성

## Assumptions

- 서버 Docker 컨테이너가 UTC로 계속 동작할 것 — if wrong: KST 하드코딩 대신 TZ 환경변수 기반으로 전환
- KST 외 타임존 사용자는 당분간 없을 것 — if wrong: 사용자별 타임존 설정 + DB 스키마 변경 필요

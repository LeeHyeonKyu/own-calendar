# 네이티브 앱 패키징 (iOS/macOS + CI/CD)

Flutter Web에서 네이티브 앱(iOS/macOS)으로 전환하고, GitHub Actions로 main 푸시 시 자동 빌드/배포한다.

## Problem

현재 Flutter Web(브라우저)으로 접근 중이다. 이는 개발 편의를 위한 임시 방편이며:
- 푸시 알림이 제한적 (브라우저 닫으면 수신 불가)
- iOS 홈화면 위젯 사용 불가
- 오프라인 사용 불가
- 앱 전환/멀티태스킹에서 네이티브 대비 UX 열위
- macOS에서 별도 앱으로 관리 불가

## Value

네이티브 앱이 되면:
- 010(알람) FCM 푸시가 안정적으로 동작
- 005(월별 위젯) 등 iOS 위젯이 홈화면에서 동작
- "매일 아침 이 앱을 첫 번째로 여는" Leading Indicator 달성에 필수
- CI/CD로 main에 push하면 자동 빌드 — 수동 빌드 반복 제거

## Solution

### Phase 1: iOS (iPhone) 네이티브 빌드 + AltStore 배포

- Flutter iOS 빌드 → IPA 파일 생성
- AltStore를 통해 iPhone에 사이드로딩
- 기존 위젯(004, 005) 포함

### Phase 2: macOS 네이티브 빌드

- Flutter macOS 빌드 → .app 파일 생성
- 직접 설치 (dmg 또는 zip 배포)

### Phase 3: CI/CD (GitHub Actions)

- main 브랜치 push 시 자동 트리거
- iOS IPA + macOS .app 빌드
- 빌드 아티팩트를 GitHub Releases에 업로드
- AltStore 소스 JSON 자동 갱신 (AltStore가 업데이트 감지)

## Scope

**Includes:**

## Approach

- iOS signing: 무료 Apple 개발자 계정 + AltStore 사이드로딩 방식
- macOS: ad-hoc 배포 (code signing 없이 배포, Gatekeeper 우회 안내)
- GitHub Actions: `macos-latest` runner 사용
  - Flutter SDK 설치 → `flutter build ios --release` → IPA 추출
  - `flutter build macos --release` → .app 압축
  - `gh release create` → 아티팩트 업로드
- AltStore 소스: GitHub Pages 또는 Releases에 `apps.json` 호스팅
- FCM: iOS APNs 키 설정 (Firebase Console → APNs Authentication Key)
- Flutter Web 빌드는 제거하지 않고 병행 유지 (개발/디버깅용)

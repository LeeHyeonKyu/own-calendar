# Feature 004: 위젯 인증 상태 연동

## Summary
로그인/로그아웃 시 iOS 홈 화면 위젯이 인증 상태를 반영한다. 로그아웃하면 위젯에서 이전 일정 데이터가 즉시 제거되고 "로그인이 필요합니다" 상태를 표시한다. 로그인하면 위젯이 최신 일정으로 갱신된다.

## Problem
현재 위젯은 인증 상태를 모른다:
- 로그아웃 후에도 이전 일정 데이터가 위젯에 그대로 남아 있음 (개인정보 노출)
- 위젯이 "일정 없음"과 "미로그인"을 구분하지 못함 — 사용자가 혼란
- 로그인/세션 복원 후 위젯이 즉시 갱신되지 않음

## Value
- PROJECT.md의 **데이터 조작의 자유 (NON-NEGOTIABLE)** — 위젯에서도 정확한 현재 상태를 보여줌
- **데이터 소유권** — 로그아웃 시 디바이스에 남은 일정 데이터를 확실히 제거

## What We Build

### Flutter 클라이언트

**AuthProvider (`auth_provider.dart`)**
- `logout()`: 위젯 데이터 클리어 (`todayEvents` 삭제 + `isLoggedIn=false` 저장) → `HomeWidget.updateWidget()` 호출
- `login()`/`register()` 성공 시: `isLoggedIn=true` 저장 → `HomeWidget.updateWidget()` 호출
- `tryRestore()` 성공 시: `isLoggedIn=true` 저장 → `HomeWidget.updateWidget()` 호출
- `_hydrateFromServer()` 401 시: 위젯 데이터 클리어 (logout과 동일)

**CalendarProvider (`calendar_provider.dart`)**
- `_updateHomeWidget()`: 기존 로직 유지 + `isLoggedIn=true`도 함께 저장 (인증 상태 확인)

**위젯 데이터 클리어 헬퍼**
- `_clearWidgetData()` 메서드: `todayEvents` 삭제 + `isLoggedIn=false` + `HomeWidget.updateWidget()` 호출
- `AuthProvider`에 추가하여 `logout()`과 `_hydrateFromServer()` 401에서 재사용

### iOS 위젯 (`OwnCalendarWidget.swift`)

**데이터 모델**
- `getEntry()`에서 `isLoggedIn` (Bool) UserDefaults 키 읽기
- `isLoggedIn == false`이면 빈 이벤트 + `isLoggedIn: false` 상태의 `EventEntry` 반환

**뷰**
- `EventEntry`에 `isLoggedIn` 필드 추가
- `isLoggedIn == false`일 때: "로그인이 필요합니다" + 앱 열기 유도 메시지 표시
- 기존 "일정이 없습니다"는 로그인된 상태에서만 표시

## Scope

**Includes:**
- AuthProvider에 위젯 데이터 클리어 로직 추가
- AuthProvider login/register/tryRestore에 위젯 인증 상태 저장
- iOS 위젯에 isLoggedIn 분기 UI 추가
- CalendarProvider._updateHomeWidget()에 isLoggedIn 플래그 동기화

**Excludes:**
- Android 위젯 (아직 미구현)
- 위젯에서 직접 로그인 (앱으로 이동만 유도)
- 위젯 탭 시 딥링크 (별도 feature)

## Acceptance Criteria
- [ ] 로그아웃 후 위젯이 "로그인이 필요합니다" 메시지를 표시한다
- [ ] 로그아웃 후 위젯에 이전 일정 데이터가 남아 있지 않다
- [ ] 로그인 후 위젯이 최신 오늘 일정으로 갱신된다
- [ ] 앱 재시작 시 자동 로그인 성공하면 위젯이 로그인 상태를 유지한다
- [ ] 서버에서 세션 만료(401) 시 위젯이 "로그인이 필요합니다"로 전환된다
- [ ] 일정이 없는 날에 로그인 상태에서는 "일정이 없습니다"가 표시된다 (기존 동작 유지)
- [ ] 위젯의 세 가지 크기(small, medium, large) 모두에서 로그인 필요 상태가 정상 표시된다

## Approach
- `home_widget` 패키지의 `saveWidgetData`/`updateWidget`을 이미 사용 중이므로, 같은 메커니즘으로 `isLoggedIn` 플래그를 추가
- AuthProvider가 직접 `home_widget`을 import하여 위젯 상태를 관리 (CalendarProvider와 독립적)
- Widget Swift 코드에서는 `isLoggedIn` 키 부재를 `false`로 처리 (하위 호환)

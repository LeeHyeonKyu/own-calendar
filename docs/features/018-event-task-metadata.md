# Event/Task 메타데이터 (참여자, 장소, 메모)

Event와 Task에 참여자, 장소, 메모 필드를 추가하고, Task가 Event에 연결되어 있으면 메타데이터를 상속한다.

## Problem

현재 Event/Task에는 제목, 시간, 설명 정도만 저장된다. "어디서", "누구와" 같은 핵심 맥락이 없다. 특히 GC에서 가져오는 일정에는 참여자, 장소, 화상회의 링크 등이 포함되는데 이를 저장하고 표시할 구조가 없다.

## Value

일정의 맥락이 완성된다. "팀 미팅"만 보이는 것과 "팀 미팅 — 회의실 A, 김팀장/이대리 참석"이 보이는 건 정보 가치가 다르다. GC 동기화(007)에서 가져오는 메타데이터도 온전히 표시 가능.

## Solution

### 메타데이터 필드

| 필드 | Event | Task | 설명 |
|------|-------|------|------|
| 참여자 (attendees) | O | O | 이름/이메일 목록 |
| 장소 (location) | O | O | 자유 텍스트 (주소, 회의실명 등) |
| 메모 (notes) | O | O | 자유 텍스트, 기존 description과 별도 |

### Task 메타데이터 상속

- Task가 Event에 related 되어 있으면 → Event의 메타데이터를 기본값으로 상속
- 상속된 값은 Task에서 오버라이드 가능
- Event 메타데이터 변경 시 → 상속 중인(오버라이드 안 한) Task에 자동 반영
- 독립 Task (Event 미연결) → 직접 입력

### GC 연동

- GC에서 가져온 attendees → 참여자 필드에 매핑
- GC의 location → 장소 필드에 매핑
- GC의 description → 기존 description 유지, 추가 메모는 notes에

## Scope

**Includes:**
- Event 모델에 attendees, location, notes 필드 추가
- Task 모델에 attendees, location, notes 필드 추가
- Task → Event 메타데이터 상속 로직 (기본값 채우기)
- 상속 vs 오버라이드 구분
- Event/Task 생성/편집 UI에 메타데이터 입력 영역
- Event/Task 상세 뷰에 메타데이터 표시
- GC 동기화 시 메타데이터 매핑 (007과 연계)

**Excludes:**
- 참여자를 Own Calendar 사용자와 매칭 (016 Invite 시스템에서 처리)
- 장소의 지도 연동 / 자동완성
- 첨부파일
- URL/링크 필드 (description이나 notes에 텍스트로 포함 가능)
- 메타데이터 기반 검색/필터

## User Stories & Acceptance Criteria

### Story 1: Event 메타데이터 입력/표시

**As a** 현규, **I want** 일정에 장소와 참여자를 기록하는 것 **so that** 일정의 맥락을 한눈에 파악한다.

**Scenario:**
- Given: Event 생성 화면
- When: 장소 "회의실 A", 참여자 "김팀장, 이대리", 메모 "자료 준비 필요" 입력
- Then: 상세 뷰에서 모든 메타데이터가 표시된다

**Acceptance Criteria:**
- [ ] Event 생성/편집 시 참여자, 장소, 메모 입력 가능 — verify: UI 확인
- [ ] 참여자는 복수 입력 가능 (이름 또는 이메일) — verify: 여러 명 입력 후 확인
- [ ] Event 상세 뷰에 메타데이터 표시 (아이콘 + 텍스트) — verify: 상세 화면 확인
- [ ] 일별/주별 뷰의 Event 카드에 장소 간략 표시 — verify: 뷰에서 장소 텍스트 확인

**Edge Cases & Errors:**
- [ ] 메타데이터 전부 비어있어도 정상 동작 (모두 optional) — verify: 빈 상태로 저장
- [ ] 장소 텍스트가 매우 긴 경우 — verify: 말줄임 처리

### Story 2: Task 메타데이터 상속

**As a** 현규, **I want** "팀 미팅" Event에 연결된 Task가 자동으로 장소와 참여자를 가져오는 것 **so that** 중복 입력하지 않아도 된다.

**Scenario:**
- Given: "팀 미팅" Event (장소: 회의실 A, 참여자: 김팀장)가 존재
- When: 이 Event에 Task "발표 자료 준비"를 연결
- Then: Task에 장소/참여자가 자동으로 채워진다

**Acceptance Criteria:**
- [ ] Task가 Event에 연결되면 메타데이터 자동 상속 — verify: 연결 후 Task 상세에서 확인
- [ ] 상속된 메타데이터를 Task에서 오버라이드 가능 — verify: Task에서 장소 변경 후 확인
- [ ] 오버라이드 안 한 필드는 Event 변경 시 자동 반영 — verify: Event 장소 변경 → Task 반영
- [ ] 오버라이드 한 필드는 Event 변경 영향 안 받음 — verify: Event 변경 후 Task 오버라이드 유지
- [ ] 독립 Task (Event 미연결) — 직접 입력만 가능 — verify: 독립 Task에서 입력 확인

**Edge Cases & Errors:**
- [ ] Task를 Event에서 연결 해제 시 — verify: 상속된 값 유지 (스냅샷) 또는 제거 (정책 결정 필요)
- [ ] Event 삭제 시 orphan Task의 메타데이터 — verify: 상속 값 스냅샷으로 보존

### Story 3: GC 메타데이터 매핑

**As a** 현규, **I want** GC에서 가져온 일정의 참여자와 장소가 표시되는 것 **so that** GC 일정 정보를 완전히 볼 수 있다.

**Scenario:**
- Given: GC에서 "팀 미팅" 일정 (참여자 3명, 장소: 회의실 B) 동기화
- When: Own Calendar에서 해당 일정 확인
- Then: 참여자, 장소가 메타데이터로 표시

**Acceptance Criteria:**
- [ ] GC attendees → 참여자 필드 매핑 — verify: GC 일정 동기화 후 참여자 확인
- [ ] GC location → 장소 필드 매핑 — verify: GC 일정 동기화 후 장소 확인
- [ ] GC 동기화 시 메타데이터도 overwrite (007 머지 전략: GC 소유 필드) — verify: GC에서 참여자 변경 → 동기화 후 반영

**Edge Cases & Errors:**
- [ ] GC 참여자가 이메일만 있고 이름 없는 경우 — verify: 이메일로 표시
- [ ] GC location이 비어있는 경우 — verify: 빈 상태 정상 처리

## Design Intent

|------|-------------|---------------|-----------------|-----------------|

| 3 | Event 상세에서 메타데이터 확인 | 📍 장소, 👥 참여자, 📝 메모 순으로 표시 | 아이콘 + 라벨로 시각적 구분 | 표시 확인 |
| 4 | Task 상세에서 상속된 메타데이터 | "(이벤트에서 상속)" 표시 + 편집 가능 | 상속 출처를 명시 — 사용자가 오버라이드 여부 인지 | 상속 표시 확인 |

## Approach

- Event 모델 확장: `location` (String?), `notes` (String?), `attendees` (JSON 배열 — [{name, email}])
- Task 모델 확장: 동일 필드 + `metaInherited` (Boolean) — 상속 상태 추적
- 상속 로직: Task 생성/연결 시 Event 메타를 Task에 복사, `metaInherited: true`. 오버라이드 시 해당 필드만 `false`로 전환
- GC 매핑: `google-sync.service.ts`의 `pullEvents()`에서 attendees, location 추출 → 새 필드에 저장
- 007 머지 전략에 attendees, location, notes를 GC 소유 필드로 추가

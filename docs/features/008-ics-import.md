# 범용 ICS Import

ICS 파일을 업로드하여 외부 캘린더의 일정을 Own Calendar로 가져온다.

## Problem

Naver, Apple Calendar, Outlook 등에 쌓여있는 과거 일정 기록을 Own Calendar로 옮길 방법이 없다. 각 서비스의 API 연동 없이도 데이터를 가져올 수 있는 범용 경로가 필요하다.

## Value

대부분의 캘린더가 ICS export를 지원하므로, ICS import만 있으면 어떤 캘린더에서든 데이터를 가져올 수 있다. PROJECT.md의 "데이터 소유권" 원칙 — 다른 플랫폼의 데이터를 자유롭게 가져와 소유할 수 있는 유일한 범용 경로.

## Solution

- ICS 파일(RFC 5545)을 파싱하여 Event로 변환
- UI에서 파일 업로드 (설정 > Import)
- Import 시 출처별 전용 캘린더 자동 생성 (예: "Naver Import 2026-09-08")
- 일회성 import — 원본과의 연결 없이 완전히 독립된 로컬 데이터
- UID 기반 중복/업데이트 처리:
  - UID 미존재 → insert
  - UID 일치 + 내용 동일 → skip
  - UID 일치 + SEQUENCE 높거나 LAST-MODIFIED 다름 → update
- Import 결과 요약 표시: "새로 추가: N건, 업데이트: N건, 중복 skip: N건"

## Scope

**Includes:**
- ICS 파일 파싱 (VEVENT → Event 변환)
- UI에서 파일 업로드
- Import 전용 캘린더 자동 생성
- UID 기반 중복 감지 및 update/skip 처리
- Import 결과 요약 표시
- ICS의 UID를 Event의 `externalId`에 저장

**Excludes:**
- 양방향 동기화 (일회성 import만)
- ICS export (Own Calendar → ICS 파일 내보내기)
- VTODO, VJOURNAL 등 VEVENT 외 컴포넌트 파싱
- 반복 일정(RRULE) 해석 — 향후 별도 feature에서 다룸
- URL을 통한 원격 ICS 구독 (CalDAV/ICS feed)

## User Stories & Acceptance Criteria

### Story 1: ICS 파일 업로드

**As a** 현규, **I want** ICS 파일을 업로드하여 과거 일정을 한번에 가져오는 것 **so that** 다른 캘린더에 쌓인 기록을 Own Calendar에서 볼 수 있다.

**Scenario:**
- Given: Naver Calendar에서 export한 ICS 파일이 있는 상태
- When: 설정 > Import에서 파일 선택 후 업로드
- Then: Import 전용 캘린더가 생성되고, 일정이 Event로 변환되어 저장된다

**Acceptance Criteria:**
- [ ] ICS 파일 업로드 시 VEVENT를 파싱하여 Event로 변환 — verify: import 후 캘린더에서 일정 확인
- [ ] Import 전용 캘린더 자동 생성 (출처 구분 가능한 이름) — verify: 캘린더 목록 확인
- [ ] Import 결과 요약 표시 (추가/업데이트/skip 건수) — verify: UI 확인
- [ ] ICS UID가 Event의 externalId에 저장됨 — verify: DB 확인

**Edge Cases & Errors:**
- [ ] 잘못된 파일 형식 (ICS가 아닌 파일) 업로드 — verify: 에러 메시지 표시, 데이터 변화 없음
- [ ] 빈 ICS 파일 (VEVENT 0건) — verify: "가져올 일정이 없습니다" 안내
- [ ] 대량 파일 (수천 건) — verify: 처리 완료, 타임아웃 없음

### Story 2: 동일 파일 재업로드 (중복 처리)

**As a** 현규, **I want** 같은 ICS 파일을 다시 올려도 중복 일정이 생기지 않는 것 **so that** 실수로 재업로드해도 안전하다.

**Scenario:**
- Given: 이미 import한 ICS 파일이 있는 상태
- When: 동일한 파일을 다시 업로드
- Then: 중복 이벤트는 skip되고 결과에 "skip: N건" 표시

**Acceptance Criteria:**
- [ ] 동일 UID + 동일 내용 → skip (중복 생성 안 함) — verify: 이벤트 수 변화 없음
- [ ] 동일 UID + SEQUENCE/LAST-MODIFIED 변경 → update — verify: 변경된 필드 반영 확인
- [ ] 새로운 UID → insert — verify: 새 이벤트 추가 확인
- [ ] 결과 요약에 각 건수 정확히 표시 — verify: UI 확인

**Edge Cases & Errors:**
- [ ] 어제 추출본 import 후 오늘 추출본 재업로드 (일부 이벤트 변경) — verify: 변경분만 update, 나머지 skip
- [ ] 다른 출처지만 우연히 UID 충돌 — verify: externalId 매칭이므로 동일 이벤트로 취급 (ICS 표준상 UID는 globally unique)

## Approach

- ICS 파싱: `ical.js` (또는 `node-ical`) 라이브러리 사용
- VEVENT 필드 매핑: SUMMARY → title, DTSTART/DTEND → startTime/endTime, DESCRIPTION → description, LOCATION → location (메타데이터 feature 이후)
- UID → Event.externalId에 저장하여 중복 감지 기반
- Import 캘린더: CalendarType.PERSONAL로 생성, 이름에 출처/날짜 포함

## Assumptions

- 주요 캘린더 서비스(Naver, Apple, Outlook)의 ICS export가 표준 RFC 5545를 준수할 것 — if wrong: 서비스별 파싱 예외 처리 추가

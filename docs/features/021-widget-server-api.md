# 위젯 서버 API 직접 호출 (AltStore App Group 우회)

iOS 위젯이 App Group UserDefaults 대신 서버 API를 직접 호출하여 데이터를 가져온다. AltStore 사이드로드 환경에서 위젯이 정상 동작하도록 한다.

## Problem

AltStore로 사이드로드 설치 시 무료 프로비저닝 프로필의 재서명 과정에서 App Group entitlement이 앱과 위젯 Extension 사이에서 분리된다. 앱에서 `HomeWidget.saveWidgetData('isLoggedIn', true)`를 저장해도 위젯의 `UserDefaults(suiteName:)`는 다른 컨테이너를 읽어 항상 `false`를 반환한다. 결과적으로 앱에 로그인해도 위젯은 "로그인이 필요합니다"만 표시한다.

USB 직접 설치(`flutter install --release`)에서는 정상 동작하지만 7일 만료 제약이 있어, AltStore가 주요 배포 채널인 현재 환경에서는 위젯이 사실상 사용 불가.

## Value

- 위젯은 앱을 열지 않고도 오늘 일정을 확인하는 핵심 사용 경험 — 이것이 안 되면 iOS 앱의 가치가 반감
- AltStore 배포 환경(무료 개발자 계정)에서 위젯이 동작해야 가족 배포가 실용적
- PROJECT.md 원칙 "데이터 조작의 자유" — 외부 서비스(App Store)에 의존하지 않고도 위젯 기능을 사용할 수 있어야 함

## Solution

위젯 Timeline Provider가 `UserDefaults`에서 데이터를 읽는 대신, 서버 API를 직접 호출한다. 인증 토큰은 iOS Keychain에 저장하여 앱-위젯 간 공유한다 (Keychain은 App Group과 달리 AltStore 재서명에서도 동일 Team ID면 유지됨).

```
[앱 로그인] → JWT를 Keychain에 저장 (accessGroup 지정)
[위젯 갱신] → Keychain에서 JWT 읽기
           → GET /api/widget/today (또는 /monthly)
           → 토큰 만료 시 refresh token으로 1회 재발급 시도
           → 네트워크 실패 시 UserDefaults 캐시 폴백
```

## Scope

**Includes:**
- 서버: `GET /api/widget/today` — 오늘 이벤트 + 태스크 경량 합본
- 서버: `GET /api/widget/monthly?year=&month=` — 월별 이벤트 맵
- Swift: `OwnCalendarProvider`/`MonthlyWidgetProvider`에 URLSession 기반 서버 호출
- Swift: Keychain에서 JWT 읽기 + refresh token으로 1회 재발급
- Flutter: `flutter_secure_storage` Keychain accessGroup 설정
- 오프라인 폴백: 기존 UserDefaults 경로를 캐시로 유지
- 기존 `HomeWidget.saveWidgetData` 호출 유지 (오프라인 폴백 데이터 원천)

**Excludes:**
- 위젯 전용 장기 토큰 발급 (대안 B — 필요 시 후속 feature)
- Android 위젯 (현재 iOS만)
- 위젯에서 데이터 쓰기 (읽기 전용)
- Push 기반 위젯 실시간 갱신 (기존 30분 타임라인 정책 유지)
- App Group entitlement 자체의 수정이나 AltStore 재서명 문제 해결

## Approach

### 서버 API

기존 `/api/events`와 `/api/tasks` 로직의 경량 합본. 위젯 전용 응답 형식으로 필요한 필드만 반환하여 payload 최소화.

### Swift 네트워크 레이어

`URLSession`을 사용한 동기식 호출 (위젯 Timeline Provider의 `getTimeline`은 completion handler 기반이므로 async/await 가능). Keychain 접근은 `Security.framework`의 `SecItemCopyMatching` 직접 사용.

### Keychain 공유

Flutter 측 `flutter_secure_storage`에 `IOSOptions(groupId:, accessibility:)` 설정. Swift 측에서 같은 accessGroup으로 `SecItemCopyMatching`. AltStore 재서명 시 Keychain accessGroup이 유지되는지 첫 빌드에서 검증 필요 — 실패 시 서버에 위젯 전용 토큰 엔드포인트 추가(대안 B)로 전환.

### 토큰 갱신

위젯에서 access token 만료 감지(401 응답) 시 refresh token으로 `POST /api/auth/refresh` 1회 호출. 성공하면 새 access token을 Keychain에 저장하고 원래 요청 재시도. 실패하면 UserDefaults 폴백.

## Assumptions

- Keychain accessGroup이 AltStore 재서명 환경에서도 앱-위젯 간 공유를 유지할 것 — if wrong: 대안 B(위젯 전용 장기 토큰)로 전환 필요
- 위젯의 30분 갱신 주기에서 서버 API 호출 1회의 네트워크 부하가 무시 가능할 것 — if wrong: 캐시 전략 강화 필요
- JWT refresh token이 위젯 Extension의 백그라운드 URLSession에서 정상 동작할 것 — if wrong: 위젯 전용 장기 토큰으로 전환

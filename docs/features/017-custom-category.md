# Custom Category (색상/이모지)

사용자가 커스텀 카테고리를 생성하고, 모든 Event/Task에 카테고리를 부여하여 시각적으로 구분한다.

## Problem

현재 Event=파랑, Task=주황으로 고정 색상만 존재한다. 일정이 늘어나면 "이게 업무인지 개인인지 운동인지" 한눈에 구분할 수 없다. TickTick처럼 카테고리별 색상 구분이 있어야 캘린더가 한눈에 읽힌다.

## Value

카테고리로 일정을 분류하면 월별 뷰에서 색상만으로 하루의 구성을 파악할 수 있다. "오늘 업무가 많은 날인지, 개인 일정이 많은 날인지"가 색으로 보인다. 카테고리별 필터링도 가능해진다.

## Solution

TickTick의 리스트/태그 시스템을 참고:

- 사용자가 카테고리를 생성 (이름 + 색상 + 이모지 선택)
- 모든 Event/Task는 반드시 하나의 카테고리에 소속
- Default 카테고리 존재 — 카테고리 미지정 시 자동 부여
- 캘린더 뷰에서 카테고리 색상으로 일정 표시
- 카테고리별 필터링 (특정 카테고리만 보기/숨기기)

### 카테고리 구성 예시

| 이름 | 색상 | 이모지 | 용도 |
|------|------|--------|------|
| 업무 | 파랑 | 💼 | 회사 관련 |
| 개인 | 초록 | 🌿 | 개인 일정 |
| 운동 | 주황 | 🏃 | 운동/헬스 |
| 가족 | 보라 | 👨‍👩‍👧 | 가족 일정 |
| (Default) | 회색 | — | 미분류 |

## Scope

**Includes:**
- 카테고리 CRUD (이름, 색상, 이모지)
- 색상 팔레트 제공 (프리셋 + 커스텀 색상)
- 이모지 선택 (선택사항 — 없어도 됨)
- Default 카테고리 (삭제 불가, 이름/색상 변경 가능)
- Event/Task에 카테고리 필드 추가 (필수, default fallback)
- 캘린더 뷰에서 카테고리 색상으로 표시 (좌측 바, 점 등)
- 카테고리별 필터 토글 (보기/숨기기)
- 카테고리 관리 UI (설정 내)

**Excludes:**
- 다중 카테고리 (1 Event/Task = 1 카테고리)
- 카테고리 계층 (상위/하위 카테고리)
- 그룹 공유 카테고리 (사용자별 독립)
- 카테고리 기반 통계/리포트

**As a** 현규, **I want** "운동" 카테고리를 주황색 + 🏃로 만드는 것 **so that** 운동 관련 일정을 시각적으로 구분한다.

**Scenario:**
- Given: 카테고리 관리 화면
- When: 이름 "운동", 색상 주황, 이모지 🏃 선택 후 생성
- Then: 카테고리가 생성되고 Event/Task 생성 시 선택 가능

**Acceptance Criteria:**
- [ ] 카테고리 생성 (이름 + 색상 필수, 이모지 선택) — verify: UI 확인

- [ ] 이모지 선택 UI (이모지 피커) — verify: 이모지 선택 동작
- [ ] 카테고리 편집/삭제 — verify: 수정 후 반영, 삭제 후 소속 일정 default로 이동
- [ ] Default 카테고리 삭제 불가 — verify: 삭제 시도 시 안내

**Edge Cases & Errors:**
- [ ] 동일 이름 카테고리 생성 — verify: 허용 (색상으로 구분 가능)

## Approach

- 새 모델: `Category` (id, name, color, emoji, isDefault, userId, sortOrder)
- Event/Task 모델에 `categoryId` 필드 추가 (FK → Category, NOT NULL, default 카테고리)
- 회원가입 시 default 카테고리 자동 생성
- 기존 Event/Task 마이그레이션: 전부 default 카테고리 부여
- 기존 006의 고정 색상(Event=파랑, Task=주황) → 카테고리 색상으로 대체
- 색상 팔레트: Material Design 색상 프리셋 12~16개 + hex 커스텀 입력
- 캘린더 필터: 클라이언트 로컬 상태 (서버 저장 불필요)

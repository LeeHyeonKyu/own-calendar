# 하단 네비게이션 통일 및 커스터마이징

하단 네비게이션 바를 중앙 관리 구조로 통일하고, 사용자가 탭 구성(표시/숨김/순서)을 커스터마이징할 수 있게 한다.

## Problem

현재 하단 네비게이션가 화면마다 다르다. 월별 뷰는 6탭, 홈은 4탭이고, 각 화면이 자체 `NavigationBar`를 정의하고 있어 비일관적이다. 새 기능(루틴, 검색 등)이 추가될수록 탭이 늘어나는데, 모든 사용자가 모든 탭을 쓰지는 않는다.

## Value

네비게이션 통일로 어떤 화면에서든 동일한 탭 경험을 제공한다. 커스터마이징으로 자주 쓰는 탭만 하단에 두고, 안 쓰는 건 숨길 수 있다. 비개발자 가족도 본인에게 필요한 탭만 남길 수 있어 진입 장벽이 낮아진다.

## Solution

### Phase 1: 네비게이션 통일

- 중앙 `NavigationShell` 위젯 하나로 모든 화면의 하단 바 통합
- 어떤 화면에서든 동일한 탭 구성
- FAB도 중앙에서 관리

### Phase 2: 커스터마이징

- 설정에서 탭 편집 UI 제공
- 각 탭의 표시/숨김 토글
- 탭 순서 드래그로 변경
- 최소 2개, 최대 6개 탭 제약 (모바일 UX)
- 사용자별 설정 저장

### 탭 후보 목록

기존 + 향후 추가 가능한 탭:

| 탭 | 기본 표시 | 비고 |
|----|----------|------|
| 월별 | O | 기본 뷰 |
| 일별 | O | |
| 주별 | O | |
| 연별 | X | 사용 빈도 낮음 |
| 가족/그룹 | O | 016에서 확장 |
| 루틴 | X | 011 이후 추가 |
| 검색 | X | 향후 |
| 설정 | O | |

## Scope

**Includes:**
- 중앙 `NavigationShell` 위젯으로 하단 바 통합 (모든 화면 동일)
- FAB 중앙 관리
- 설정에서 탭 편집 UI (표시/숨김 토글 + 순서 드래그)
- 최소 2개, 최대 6개 탭 제약
- 사용자별 탭 설정 저장 (서버 또는 로컬)

**Excludes:**
- 탭 아이콘/라벨 커스터마이징 (이름/아이콘 변경)
- 사용자 정의 탭 추가 (URL이나 외부 링크)
- 태블릿/데스크톱 사이드 네비게이션 (별도 feature)

## User Stories & Acceptance Criteria

**Scenario:**
- Given: 앱 사용 중
- When: 월별, 일별, 주별 등 어떤 화면으로 이동해도

**Acceptance Criteria:**
- [ ] 모든 화면에서 동일한 하단 탭 표시 — verify: 화면 전환 시 탭 구성 일치 확인

**Edge Cases & Errors:**

- [ ] 뒤로가기 시 탭 상태 유지 — verify: 뒤로가기 후 탭 확인

### Story 2: 탭 커스터마이징

**As a** 현규, **I want** 하단 탭에서 "연별"을 숨기고 "루틴"을 추가하는 것 **so that** 자주 쓰는 탭만 보인다.

**Scenario:**
- Given: 기본 탭 구성 상태
- When: 설정 > 탭 편집에서 "연별" 숨김, "루틴" 표시 설정
- Then: 하단 바에 변경된 구성이 즉시 반영

**Acceptance Criteria:**
- [ ] 설정에서 탭별 표시/숨김 토글 — verify: 토글 후 하단 바 변화 확인
- [ ] 드래그로 탭 순서 변경 — verify: 순서 변경 후 하단 바 반영
- [ ] 최소 2개 탭 필수 (2개 이하로 줄이기 불가) — verify: 마지막 2개 탭 숨김 시도 시 안내
- [ ] 최대 6개 탭 (초과 시 안내) — verify: 7번째 탭 표시 시도 시 안내

**Edge Cases & Errors:**
- [ ] 현재 보고 있는 탭을 숨길 경우 — verify: 첫 번째 표시 탭으로 자동 이동

- [ ] 가족 구성원별 다른 탭 설정 — verify: 각 계정 독립 설정 확인

**As a** 가족, **I want** 필요한 탭만 남기는 것 **so that** 복잡하지 않게 앱을 사용한다.

**Scenario:**

**Acceptance Criteria:**
- [ ] 2개 탭만으로 정상 사용 가능 — verify: 2탭 구성에서 모든 기능 접근 확인

## Approach

- 중앙 `NavigationShell` 위젯: `go_router`의 `ShellRoute` 패턴 활용
- 탭 레지스트리: 가능한 모든 탭 목록을 중앙에서 관리 (id, icon, label, route, default visible)
- 사용자 설정: `UserPreference` 모델에 `navTabs` 필드 (탭 id 배열 — 순서 포함)
- 새 탭 추가 시: 레지스트리에 등록만 하면 커스터마이징 UI에 자동 노출
- 기존 각 화면의 개별 `NavigationBar` + FAB 코드 제거, `NavigationShell`로 대체

## Assumptions

- 하단 탭 수가 3~6개 범위에서 유지될 것 — if wrong: "더보기" 탭이나 스크롤 네비게이션 검토

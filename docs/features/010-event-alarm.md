# 일정 알람 (N분 전 / 정시 알림)

각 일정에 대해 N분 전 또는 정시 알림을 설정하고, 서버가 시간에 맞춰 푸시 알림을 발송한다.

## Problem

일정이 있어도 알림이 없으면 놓친다. 현재 Own Calendar에는 알림 기능이 없어서, 일정을 확인하려면 앱을 직접 열어야 한다. 다른 캘린더 앱을 계속 병행하게 되는 이유 중 하나.

## Value

알림이 있어야 "여기만 보면 된다"가 완성된다. 통합 뷰에 일정이 모여 있어도 알림이 오지 않으면 여전히 GC/Naver 앱의 알림에 의존하게 된다. PROJECT.md의 Leading Indicator("매일 아침 이 앱을 첫 번째로 여는가")에 직결.

## Solution

- 각 일정에 알림 설정: N분 전 (5, 10, 15, 30, 60분 등) 또는 정시(일정 시작 시각) 또는 알림 끄기
- 서버 스케줄러가 알림 시각을 계산하여 시간에 맞춰 FCM 발송
- 클라이언트에서 알림 수신 및 표시
- 일정별 개별 설정 + 기본값 설정 (설정에서 디폴트 알림 시간 지정)

## Scope

**Includes:**
- 일정별 알림 설정 UI (N분 전 선택 / 정시 / 알림 끄기)
- 기본 알림 설정 (설정에서 디폴트 값 지정 — 새 일정 생성 시 자동 적용)
- 서버 알림 스케줄러 (일정 시각 기준으로 알림 시각 계산, 발송 큐)
- FCM 푸시 알림 발송
- 알림 탭 시 해당 일정으로 이동

**Excludes:**
- 인앱 알림 목록 / 알림 센터 (별도 feature)
- 반복 일정의 알림 (반복 기능 이후)
- 가족 일정 알림 (가족 구성원의 일정 변경 알림)
- 네이티브 앱 패키징 — 별도 feature. Web Push(Service Worker)로 우선 지원, 네이티브 앱 전환 후 FCM으로 교체

## User Stories & Acceptance Criteria

### Story 1: 일정에 알림 설정

**As a** 현규, **I want** 일정에 "30분 전 알림"을 설정하는 것 **so that** 일정을 놓치지 않는다.

**Scenario:**
- Given: 일정을 생성하거나 편집하는 상태
- When: 알림 옵션에서 "30분 전" 선택
- Then: 해당 일정 30분 전에 푸시 알림이 온다

**Acceptance Criteria:**
- [ ] 일정 생성/편집 시 알림 옵션 선택 가능 (5, 10, 15, 30, 60분 전, 정시, 끄기) — verify: UI 확인
- [ ] 선택한 시간에 푸시 알림 수신 — verify: 실제 알림 수신 테스트
- [ ] 알림 탭 시 해당 일정 상세로 이동 — verify: 알림 탭 후 화면 전환 확인
- [ ] 알림 시각이 DB에 저장됨 — verify: DB 확인

**Edge Cases & Errors:**
- [ ] 이미 지난 일정에 알림 설정 — verify: 알림 발송 안 함 (과거 시각 무시)
- [ ] 일정 시간 변경 시 알림 시각도 재계산 — verify: 수정 후 알림 시각 갱신 확인
- [ ] 일정 삭제 시 예약된 알림도 취소 — verify: 알림 미수신 확인

### Story 2: 기본 알림 설정

**As a** 현규, **I want** 기본 알림을 "10분 전"으로 설정해두는 것 **so that** 새 일정마다 매번 알림을 설정하지 않아도 된다.

**Scenario:**
- Given: 설정에서 기본 알림을 "10분 전"으로 지정한 상태
- When: 새 일정 생성
- Then: 알림이 자동으로 "10분 전"으로 설정되어 있다

**Acceptance Criteria:**
- [ ] 설정에서 기본 알림 시간 선택 가능 — verify: 설정 UI 확인
- [ ] 새 일정 생성 시 기본값 자동 적용 — verify: 일정 생성 후 알림 설정 확인
- [ ] 개별 일정에서 기본값 오버라이드 가능 — verify: 기본값과 다른 알림 설정 후 확인

**Edge Cases & Errors:**
- [ ] 기본 알림 "끄기" 설정 시 새 일정에 알림 없음 — verify: 일정 생성 후 알림 미설정 확인
- [ ] GC에서 가져온 일정에도 기본 알림 적용 여부 — verify: GC 일정은 GC 알림 설정을 따르거나 별도 정책 확인

## Approach

- 서버: 알림 스케줄러 — cron 또는 지연 큐(예: `bull`, `agenda`)로 알림 시각에 맞춰 FCM 발송
- DB: Event에 `reminderMinutes` 필드 추가 (null = 기본값 사용, 0 = 정시, -1 = 끄기)
- User에 `defaultReminderMinutes` 설정 추가
- FCM: 서버에서 발송. 클라이언트는 FCM 토큰을 서버에 등록
- 우선 Web Push(Service Worker) 지원, 네이티브 앱 전환 후 FCM 네이티브로 교체

## Assumptions

- FCM이 iOS/Android/Web 모두에서 안정적으로 동작할 것 — if wrong: 플랫폼별 알림 분기
- 서버 스케줄러가 가족 규모(수백 건)의 알림을 지연 없이 처리할 것 — if wrong: 큐 시스템 도입
